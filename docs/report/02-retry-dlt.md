# Ретраї та Dead Letter Topic у notification-service

## Топологія топіків

Споживач `ShipmentEventListener` (група `shipment-notification-group`) читає `shipment.events`. Допоміжні топіки створює сам `notification-service` під час старту.

| Топік | Призначення | Затримка перед обробкою |
|---|---|---|
| `shipment.events` | основний, сюди публікує Outbox relay із `shipment-service` | — |
| `shipment.events-retry-0` | друга спроба | 1 с |
| `shipment.events-retry-1` | третя спроба | 2 с |
| `shipment.events-retry-2` | четверта спроба | 4 с |
| `shipment.events-dlt` | події, які не вдалося обробити | — |

Кількість спроб і затримки задаються властивостями `app.kafka.retry.*` (змінні `APP_KAFKA_RETRY_*`).

## Поділ помилок

- **Повторювані** — будь-який виняток з `ShipmentEventHandler` (наприклад, недоступна база). Подія проходить усі retry-топіки і після четвертої невдалої спроби потрапляє в DLT.
- **Неповторювані** — зіпсований JSON та порушення контракту (`InvalidShipmentEventException`: немає `eventId` або `payload.shipmentId`). Подія йде в DLT одразу, без ретраїв.

Повторна спроба не блокує основний топік: невдалий запис пересилається в наступний топік, а споживач одразу бере наступну подію.

Значення читається як сирі байти й перетворюється в `ShipmentCreatedEvent` уже в слухачі. Завдяки цьому зіпсоване повідомлення не зупиняє `poll()` і потрапляє в DLT у незмінному вигляді.

`@DltHandler` записує в лог топік, розділ, зсув, ключ, клас і текст винятку та вміст повідомлення.

## Результати тестування

`ShipmentEventListenerDltIntegrationTest` (`@EmbeddedKafka`, обробник підмінено моком):

| Сценарій | Результат |
|---|---|
| Обробник завжди кидає виняток | 4 виклики обробника, подія в `shipment.events-dlt` з початковим вмістом |
| Зіпсований JSON | подія в DLT, ретраїв і викликів обробника немає |
| Подія без `eventId` | подія в DLT, ретраїв і викликів обробника немає |
| Дві невдалі спроби, третя успішна | 3 виклики обробника, DLT порожній |

Запуск:

```bash
cd notification-service && mvn test
```

Перевірка в Docker Compose: подія з `POST /shipments` дійшла до обробника, а сім зіпсованих повідомлень з усіх трьох розділів `shipment.events` опинилися в `shipment.events-dlt`.
